# 085 — The verdict is asked for in the prompt

Status: accepted
Cites: Verdict, Judged, Reported, RepairReport, Offer, OutputMode, unfenced, unstringed, unwrapped, unenveloped, judged, judge_briefed, attempt_briefed, asks_for_output, output_mode, JUDGE_PREAMBLE, PREAMBLE, classify, crates/fiddle-runtime/src/agent/mod.rs, crates/fiddle-runtime/src/toil/review.rs, crates/fiddle-runtime/tests/agent.rs, crates/fiddle-acceptance/tests/toil.rs, the_evaluation_sends_no_structured_output_schema_and_asks_for_the_verdict_in_its_preamble, a_verdict_reads_in_each_shape_a_recorded_gateway_body_arrived_in, an_evaluation_that_answers_nothing_is_told_apart_from_one_that_answers_wrongly, a_verdict_is_read_through_one_fence_and_prose_beside_one_is_refused, the_evaluation_asks_for_its_answer_in_the_prompt_and_the_repair_asks_the_provider, no_schema_a_toil_run_sends_carries_a_combiner_at_the_top_of_itself

## Context

Five times on 2026-09-03 and 2026-09-04 a live toil run against one LiteLLM deployment, `https://litellm.firn.snplow.net/v1`, failed because a typed answer arrived in a shape this build could not read. `claude-opus-5` called `json_tool_call`, a tool nothing had registered. `bedrock/moonshotai.kimi-k2.5` returned no message and no tool call. `claude-sonnet-5` wrapped a report in `{"parameters": {...}}`, then in `{"parameters": "{...}"}` with the report double-encoded, then in `{"verdict": "{...}"}`, under a key that is the payload's own tag. ADR 083 records the first four and the readers written for them.

This build asked for those answers as OpenAI structured output: `response_format: {type: json_schema, ...}`. Anthropic's API has no such field. A gateway fronting Anthropic must emulate it, and each emulation is a choice the gateway makes, which a version bump can change and a second deployment will make differently. Five shapes from one deployment in two days is the evidence. Four were read by narrow tolerances. The fifth was refused, because a reader that must decide whether a single key belonging to the target type is an envelope or the payload has stopped reading and started guessing, and this project's rule is that a tool which cannot answer refuses rather than answers partly.

The operator decided: stop asking the provider for structured output, ask for JSON in the prompt, and parse the text. This record carries that decision out for `Verdict` and records why `RepairReport` was left where it is.

This record grades each claim as ADR 083 does. MEASURED means a test in this repository observes the behaviour or the claim was read off a request this build sent. ARGUED means the claim is read off the source and no test fails if it is wrong. OBSERVED means a live run did the thing.

## Decision

**The evaluation asks for its verdict in the prompt and asks the provider for no structured output. The repair step still asks the provider.**

### Whether `OutputMode::Prompted` reaches a request through `prompt_typed`

ARGUED, read off `rig-agent 0.41.0`: **it does not.** `TypedPromptRequest::from_agent` in `src/agent/prompt_request/mod.rs` builds the untyped request and then overwrites two fields of its runner. Line 732 sets the output schema to the typed parameter's own. Line 739 sets `output_mode` to `OutputMode::Native`. Neither line is conditional. So an `OutputMode::Prompted` named on the builder is discarded on that path exactly as `fiddle-n6o8` measured `OutputMode::Tool` to be, and for the same reason. rig's comment beside line 739 says typed prompts pin `Native` on purpose, and that the untyped `output_schema` and `output_mode` API is the route for anything else.

ARGUED, read off the same crate: the untyped path keeps the mode. `AgentRunner::from_agent` in `src/agent/runner.rs` copies the agent's `output_schema` at line 254 and its `output_mode` at line 255 and overrides neither. `PromptRequest::from_agent` at `src/agent/prompt_request/mod.rs` line 226 wraps that runner and touches neither field. So the builder's `OutputMode::Prompted` reaches a request through `prompt` and never through `prompt_typed`. The mechanism that is load-bearing is the untyped call, and a return to `prompt_typed` for the evaluation would put the schema back on the wire silently.

### What rig does with the schema under `Prompted`

ARGUED, read off `src/agent/completion.rs` in the same crate. The resolver at line 79 returns `Prompted` when a schema is present and the caller named `Prompted`. It returns `Native` when no schema is present, whatever the caller named, so dropping `.output_schema::<Verdict>()` from the builder would not remove the constraint but would remove the shape from the prompt. Under `Prompted`:

- lines 419 to 425 append to the preamble the sentence `Respond with ONLY a single JSON object that conforms to this JSON Schema. Do not include any prose, explanation, or markdown code fences.` followed by the schema serialised compactly, and line 444 sends the whole as the leading system message;
- line 489 sets the provider's native constraint only when the resolved mode is `Native`, so under `Prompted` the request's `output_schema` stays empty, and `rig-core 0.41.0`'s OpenAI provider at `src/providers/openai/completion/mod.rs` line 1841 builds a `response_format` only from a present `output_schema`;
- line 353 picks an output tool name only under `Tool`, so no synthetic tool is advertised;
- `src/agent/run/mod.rs` line 790 re-prompts for structured output only when an output tool name is set, so under `Prompted` the model's final text is returned as it arrived, with no client-side validation and no retry.

So rig puts the shape in the prompt itself, and this build does not write it into `JUDGE_PREAMBLE` by hand. What rig does not do on this path is read the text: the typed path's fence-and-prose fallback lives in the typed request's send, and the untyped path returns a `String`.

### The route

MEASURED off the request this build sends: `judge_briefed` in `crates/fiddle-runtime/src/agent/mod.rs` names `.output_schema::<Verdict>()` and `.output_mode(OutputMode::Prompted)` on the builder, drives the untyped `prompt`, and reads the returned text through `judged`. `Offer::Judge.output_mode()` is `Prompted` and `Offer::Repair.output_mode()` is `Native`, and `asks_for_output` writes `prompted` or `native` into the transcript's brief beside `tool_choice`, which `the_evaluation_asks_for_its_answer_in_the_prompt_and_the_repair_asks_the_provider` holds. `the_evaluation_sends_no_structured_output_schema_and_asks_for_the_verdict_in_its_preamble` in `crates/fiddle-runtime/tests/agent.rs` captures the evaluation's request off a stub that obeys the tool choice it is sent: `output_schema` is `None` on the one request sent, the system message opens with the caller's brief, and it carries the verdict's own schema whole and rig's sentence asking for one object. `the_schema_the_repair_step_sends_is_the_reports_own_and_the_newtype_moves_nothing` reads `Some` off the same field on the repair side in the same file, so the `None` is the evaluation's choice and not a field the capture cannot see.

MEASURED through the binary: `no_schema_a_toil_run_sends_carries_a_combiner_at_the_top_of_itself` in `crates/fiddle-acceptance/tests/toil.rs` reads every request body of one whole toil run off the loopback socket. It counted two `response_format` schemas per run and now counts one, the report's. It requires that every request carrying the judge's brief carries no `response_format` and carries `"enum":["accepted","rejected"]` in its system message, and that there are at least two such requests, because the judge in that world reads before it answers.

### Reading the text

MEASURED: `judged` refuses blank text as no answer, strips one fence with `unfenced`, and parses the rest through `Judged`, which is `unenveloped` and then `Verdict`. `unfenced` moved from `crates/fiddle-runtime/src/toil/review.rs` to `crates/fiddle-runtime/src/agent/mod.rs` unchanged, and the ambiguity review imports it; `the_recorded_gateway_answer_is_read_through_the_fence_it_arrived_in` still drives it against the recorded fenced body. `Judged` no longer implements `JsonSchema`, because nothing types a request by it any more. It is the reader and only the reader.

MEASURED against the recorded gateway bodies: `a_verdict_reads_in_each_shape_a_recorded_gateway_body_arrived_in` derives each framing from a fixture under `tests/fixtures/gateway-real/` rather than retyping it. The fence with its leading space is cut out of `review-answer.json` around the object it carries, and the lane first puts that object back and requires the recorded body byte for byte. The `parameters` envelope is `repair-report-answer.json` with the report swapped for a verdict. The string is `repair-report-string.json` with its string swapped for a verdict serialised as one. Each helper requires the fixture to be one `parameters` member of the recorded kind. An acceptance and a rejection carrying a finding go through a whole `judge_briefed` in each shape. So the three shapes a live run has produced still read, and a fixture that changes shape changes the lane.

MEASURED, the floor: `an_answer_that_is_not_a_verdict_is_refused_and_the_refusal_names_the_verdict` carries nine answers through a whole evaluation, and each is refused with `the verdict did not match the schema:` and the field or variant that failed. Four are new: prose before an object, a fence followed by prose, two fenced objects, and an empty fence. `a_verdict_is_read_through_one_fence_and_prose_beside_one_is_refused` in the module's own tests holds the same floor on `judged` directly and requires that an answer which arrived is never refused as absent. `an_evaluation_that_answers_nothing_is_told_apart_from_one_that_answers_wrongly` holds that blank text is `the model returned no final content at all`. `a_report_inside_two_json_strings_is_refused_rather_than_decoded_twice` is untouched and still bounds `unstringed`.

ARGUED, and it is a narrowing: the typed path's fallback read the first balanced JSON value out of any prose, and ADR 083 relied on it for the fenced verdict. `unfenced` tolerates one fence and nothing else, so an answer with prose before or after the object is refused where rig would have read it. That is the project's rule and not an accident. A reader that searches text for the first value it can parse is choosing among candidates, and the fifth shape is what choosing looks like when it goes wrong. The recorded fenced body is the only fenced answer a live run has produced, and it reads.

ARGUED: `tool_choice` did not move. `Offer::Judge` stays `Auto`, because a text answer is the only channel a read-only step has and `Required` forbids it, which `fiddle-n6o8` measured. Under `Prompted` that reasoning holds for any step whose answer is text. The repair step's answer is still the provider's structured output, so `Offer::Repair` stays `Required`, and `the_repair_step_still_obliges_a_tool_call_and_a_gateway_that_obeys_leaves_it_no_answer` still pins the defect ADR 083 records there.

### `RepairReport` stays where it is, and the reason is a measurement

OBSERVED, and it is the measurement the brief asked for: this build has already run the report through `Prompted` once. v0.4.0 named `OutputMode::Prompted` for the report to dodge the `json_tool_call` rename, and run 32580288040 returned a report with no `summary` field after fifteen minutes of work; the run failed on deserialization. `5eee54b` reverted to provider enforcement on that evidence, and `46a87f1` recorded that neither `Prompted` nor `Tool` had enforced the schema. `Native` then held the report's fields through every live run since. The five failures above were all in the gateway's wrapping of a correctly shaped answer and never in the answer's fields.

ARGUED from that record: the schema guarantee buys the report its six fields, one of them nested, and two optional fields whose descriptions instruct the model, and it was measured to lose a required field without the guarantee. It buys the verdict one required word from an enum of two, and `fiddle-n6o8` had already replaced the derived schema with a hand-written one so that `required` covers `verdict` alone. Losing the guarantee there costs little, and is now measured to cost nothing on the shapes recorded so far. So `Verdict` moved and `RepairReport` did not.

ARGUED, what would decide it later: a recorded report answer in the fifth shape, a key of the report's own wrapping a string, is the evidence that the wrapping problem has reached the report and outweighs the one lost field. Until then every recorded report failure is one `unenveloped` reads, and the report's one `Prompted` failure was not. The transcript now records `output: native` on the report's brief and `output: prompted` on the verdict's, so the next failed run says which mechanism carried the answer.

## Consequences

- The evaluation's request carries no `response_format` and no synthetic tool. Its system message carries `JUDGE_PREAMBLE`, then rig's sentence, then the verdict's schema.
- A gateway fronting Anthropic has nothing to lift into a tool for the evaluation, so the five recorded wrapping shapes cannot recur there. They can still recur on the report, and `unenveloped` still reads four of them.
- The verdict's schema still carries no top-level combiner. `no_tool_schema_this_build_sends_carries_a_top_level_combiner` holds both schemas to the rule, so moving the verdict back onto the wire cannot bring one with it.
- ADR 083's claim that `Prompted` gives up the schema on the wire for nothing `Auto` does not already give was right on the evidence of 2026-09-03 and is superseded by this record on the evidence of the two days after. ADR 083 says so at each passage this record supersedes.
- A future rig that stops honouring `Prompted` on the untyped path, or a return to `prompt_typed` for the evaluation, reds `the_evaluation_sends_no_structured_output_schema_and_asks_for_the_verdict_in_its_preamble` and `no_schema_a_toil_run_sends_carries_a_combiner_at_the_top_of_itself`, so the mechanism cannot change silently.
