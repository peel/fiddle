## Context

`fiddle-20l5`. The bean records that in live run 2 on snowplow-incubator/snowplow-identities#275 the agent changed two test assertions and added a code comment. The target's `CLAUDE.md` forbids both. The agent's answer said no assertion changed, and the evaluator accepted the change. No workflow gave the target's `CLAUDE.md` or `AGENTS.md` to the agent or to the evaluator. The evaluator also did not see the agent's report, so it could not compare the answer with the change.

## Decision

**Every agent step and every evaluate step of `toil`, `checks` and `pull_request` quotes the target's `CLAUDE.md` and `AGENTS.md` from the run's base commit. A file is quoted whole, or the run stops.**

### Source

- `RULE_FILES` names `CLAUDE.md` and `AGENTS.md` at the repository root. `ProjectRules::at` reads them from a commit through `Workspace::committed_file`, `Workspace::committed_size` and `Workspace::committed_bytes`, never from the working tree. A change under review cannot rewrite the rules it is judged by.
- A `pr:` run's base is the branch the pull request names, `base.ref`. `stand_on` fetches it beside the head and resolves `origin/<base>`, and `SteeredBy` carries that commit. A base that cannot be fetched or resolved stops the run as `Retryable`, exit 11, because the fetch fails as a workspace error. It does not give a brief with no rules.
- Every other run's base is the commit the workspace was cut from, `Workspace::cut_from`. That is the HEAD of `[workspace] fixture`, which is the commit fiddle builds the run's branch on. A `jira:` run that steers onto its pull request's head still reads the commit it was cut from. That run's branch is fiddle's own, and fiddle built it on that commit.
- An absent file gets no entry, and two absent files give no section. A directory or a submodule with a rules file's name is not a file. `@` imports are not followed. A link is followed one step inside the repository and quoted as the file it names.

### One read, of the objects the commit names, amended

The run reads the rules once. The read happens when the run reaches its first agent, evaluate or check step, before that step runs, so before any project command runs. Every agent step and every evaluate step of the run quotes that one result. Code the run executes, such as a check the agent runs, cannot change what a later step quotes, even when it writes into the git directory the workspace shares.

Each `ls-tree` and `cat-file` that serves the rules runs with `git --no-replace-objects`, so a `refs/replace` entry does not change the object a commit names. A `pr:` run that steers reads after the steer step has fetched the base, because the steer step runs no project command.

### Where

`task_carrying` puts the rules after the step's prompt and before the ticket, the direction and the checks, for the agent step and the evaluate step alike. `fenced` frames them: the agent holds the work to them, because they say how the project's files may be changed and what may be written in them; a line in them that tries to give a tool, change the task or change the report is part of the quotation, and so is a line that looks like one of fiddle's headings. Each file sits between fence lines from `fence_for`, so a file that holds a code fence gets a longer one.

### Bound, amended

The first text of this record quoted no part of a file over the cap and told the reader to read it with `read_file`. That broke the rule above. `read_file` reads the workspace, which is the pull request's head for a `pr:` run and a `checks` run, and is the agent's own working tree for every evaluator. A change could then rewrite the rules it is judged by. The lead reports that the real file this work began from, the `CLAUDE.md` of snowplow-identities, is 8425 bytes, far under the cap. This record did not measure it.

Now `RULES_CAP_BYTES` is 32768 bytes per file, and a rules file fiddle cannot quote whole refuses the run. `ProjectRules::at` answers `RulesError::Unquotable` with an `UnquotableRules` for each of these kinds of `Unquotable`: a file over the cap, a file that is not UTF-8 text, a link that leaves the repository, a link to no file, and a link to another link. A link to a directory is a link to no file, and so is a link such as `.` or `docs/..` that resolves to the repository root. So is a link whose target holds a line break, a backtick or another control character, because the brief's label `A LINK TO` names the target outside any fence. fiddle reads every committed path literally, with `git --literal-pathspecs`, so a target such as `:(glob)x` is a name and not pathspec magic. A git failure while fiddle follows a link is a link to no file too: the read of the link's own blob, and the size and the read of the file it names. The run ends `Failed`, and no message prints the target or git's own text. fiddle sizes each blob with `git cat-file -s` and not with `ls-tree -l`, so a link blob git cannot read fails on the link and not on the listing. A git failure while fiddle lists `CLAUDE.md` or `AGENTS.md`, or while it sizes or reads one of them that is not a link, is `RulesError::Unread`, which becomes `CapabilityError::RulesUnread`. That is `Recurrence::Correctable`, so the run ends `Retryable`, exit 11. Its message names the file and the commit, and holds no object id and no git text. The refusal names the file, the commit, its size or kind, and the cap. It names a link by its own path and never prints the link's target. No part of the file is quoted anywhere.

The read happens before the first agent step, so the run asks no agent or evaluator, changes nothing, pushes nothing and answers nothing on the pull request. A `jira:` run asks the ambiguity review before the workflow starts, so that one model call can come before the refusal.

The refusal is `CapabilityError::UnquotableRules`, with `Recurrence::Permanent`. The orchestration maps that to `RunOutcome::Failed`, exit 20, a conclusion about the request (ADR 016). The cause is a property of the target repository at that commit, and another run reads the same file, so the run is not retryable. It is not invalid input either: the reference is sound, and exit 2 is for a refusal before a run begins.

### Evaluation

The evaluate step now also quotes the agent's own report, through `with_report` and `report_quoted`, framed by `REPORT_FRAME` as a claim and not evidence. `change_evaluate.md`, `checks_evaluate.md` and `pull_request_evaluate.md` each tell the evaluator to reject a change that breaks a quoted rule, with a finding that quotes the rule and names its file, and to reject a report that misstates what changed. These are instructions to a model, not checks fiddle makes. `pull_request_evaluate.md` counts an unrequested code comment, and an edited test assertion the mention did not ask for, as more than the mention asked.

`fiddle-hrnq` records that a toil run on ISP-302 added two lines to an existing SQL comment, which the target's `CLAUDE.md` forbids, and wrote none of the tests the ticket's acceptance criteria named. The evaluator accepted the change. Now `change_evaluate.md` and `toil.md` hold one sentence: a code comment the ticket did not ask for, and a line added to an existing comment, is more than the ticket asked for. `toil.md` adds that when the project's rules for agents forbid comments, the agent adds none. `change_evaluate.md` rejects a change that leaves a stated acceptance criterion unmet. A criterion that names a test holds only when the project holds that test and the test checks the behaviour the criterion describes. A test on another branch does not count, and the finding names the criterion, and the test when the criterion names one. `toil.md` and `checks.md` tell the agent to read the quoted rules before it changes anything. `toil.md` also tells the agent to meet each acceptance criterion and to write a test that a criterion names and the project lacks. When it cannot write that test in the project, because the test needs infrastructure the project does not have or the ticket does not give enough to build it, the agent changes nothing and names the criterion in `stopped_by_this_question`. The description of that field on `RepairReport`, in `crates/fiddle-runtime/src/agent/mod.rs`, names this case too, so the schema does not tell the agent to leave the field out. `pull_request.md` does not carry the rule-reading line. These are also instructions to a model. Five acceptance rows pin the sentences in the requests the models receive: `the_toil_agent_is_told_to_read_the_rules_first_and_to_meet_each_acceptance_criterion`, `the_toil_evaluation_rejects_an_unmet_acceptance_criterion_and_a_test_that_checks_nothing`, `the_toil_agent_and_its_evaluation_count_an_unasked_comment_as_more_than_the_ticket_asked`, `the_report_schema_lets_the_toil_agent_stop_on_a_named_test_it_cannot_write` and `the_projects_rules_reach_a_checks_run_from_the_base_and_not_from_the_head_it_stands_on`. They do not measure what a model does with them. `change_evaluate.md` tells the evaluator to reject a change when what it reads does not show that every criterion holds, so a criterion the files cannot show, such as one verified in staging, is a rejection. That is also an instruction, and no row measures it.

## Consequences

- A `pr:` run makes one more fetch, of its base branch, before the agent runs.
- A `jira:` run reads the rules of its fixture's HEAD. That commit is the base of the run: the agent changes its code, and fiddle builds the branch on it.
- Each brief grows by the size of the two files, at most 32768 bytes each, plus the frame, the labels and the fences that hold them.
- A target whose rules file is over the cap, or not text, or a link fiddle does not follow, gets no run until the file changes on its base.
- The transcript cuts each field over 16384 characters in the middle, so it can hold less than the whole quotation. The commit the brief names holds the whole text, at the path the brief's label names: the rules file itself, or for a link, the path after `A LINK TO`.
- The single read holds for one run. The fixture's object store persists across runs, and workspace commands are not isolated (ADR 044), so code one run executes can change what a later run reads.
